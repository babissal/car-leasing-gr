<action>
Update server.js:

1. Add at top (after existing requires):
   const { scrape: scrapeInstacar } = require('./scrapers/instacar')
   const { validateOffer } = require('./lib/schema')

2. In-memory store (module-level variable):
   let store = { offers: [], scrapedAt: null, errors: [] }

3. Replace stub POST /api/scrape with real implementation:
   - Read duration (integer) and advancePayment (integer, default 0) from req.body
   - Validate: duration must be one of [12, 24, 36, 48]; if not, return 400 { error: 'Invalid duration. Must be 12, 24, 36, or 48.' }
   - Run scraper: const offers = await scrapeInstacar({ duration, advancePayment })
   - On scraper error: store.errors = [err.message]; return 500 { error: err.message, offers: [], scrapedAt: new Date().toISOString() }
   - On success: store = { offers, scrapedAt: new Date().toISOString(), errors: [] }
   - Return 200: { offers: store.offers, scrapedAt: store.scrapedAt, errors: store.errors, count: store.offers.length }

4. Add GET /api/offers endpoint:
   - Returns current store contents: { offers: store.offers, scrapedAt: store.scrapedAt, errors: store.errors, count: store.offers.length }
   - Useful for refreshing UI without re-scraping

5. Add error handler middleware at end of file (before app.listen):
   app.use((err, req, res, next) => { console.error(err); res.status(500).json({ error: 'Internal server error' }) })

Keep the async handler wrapped in try/catch — unhandled promise rejections must not crash the server.
</action>

- POST /api/scrape with { duration: 99 } returns HTTP 400 with JSON containing 'error' key
- POST /api/scrape with { duration: 24 } triggers the scraper (observable via console.log in scraper or network activity)
- On scraper success: response is HTTP 200 with { offers: [...], scrapedAt: string, count: number }
- On scraper error (e.g. site unreachable): response is HTTP 500 with { error: string } — server does NOT crash
- GET /api/offers returns the same data as last successful scrape (or empty offers if none yet)
- Module-level store variable is present in server.js
</acceptance_criteria>
</task>
