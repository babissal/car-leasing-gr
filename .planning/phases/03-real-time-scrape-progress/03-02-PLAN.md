<threat_model>
<threats>
<threat id="T-03-04" severity="low">
Double-click race: User clicks "Scrape" twice before the first scrape completes, launching 2 concurrent EventSource connections and 2 full Playwright sessions (10 browser contexts). Mitigated by setting scrapeBtn.disabled = true immediately in the click handler — second click is a no-op because the button is disabled.
</threat>
<threat id="T-03-05" severity="low">
EventSource auto-reconnect after done: After server calls res.end(), the browser's EventSource detects the closed connection and auto-reconnects after 3s, which would start a second silent scrape. Mitigated by calling es.close() synchronously as the first line inside the done event listener, before the connection-close is detected.
</threat>
<threat id="T-03-06" severity="low">
setSourceStatus called before progressEl is in the DOM: If index.html does not have <div id="progress-list">, document.getElementById('progress-list') returns null and setSourceStatus throws on null.querySelector(). Mitigated by ensuring the HTML change (task 03-02-01) is applied before app.js is tested, and by adding a null guard in setSourceStatus.
</threat>
</threats>
<mitigations>All threats are mitigated in the implementation tasks below. No high-severity threats identified — this is a localhost tool with a single user and no authentication requirements.</mitigations>
</threat_model>
