<threat_model>
<threats>
<threat id="T-03-01" severity="low">
SSE endpoint timeout: Express socket timeout closes connection during 60-120s scrape, triggering EventSource auto-reconnect and duplicate scrape. Mitigated by req.socket.setTimeout(0) called immediately after res.flushHeaders().
</threat>
<threat id="T-03-02" severity="low">
Client disconnect leaves Playwright browsers running: When the browser tab closes, req.on('close') fires but scraper promises continue executing because there is no AbortSignal passed to individual scrapers. Mitigated by setting aborted=true and guarding all res.write() calls — no crash occurs, scrapers complete silently.
</threat>
<threat id="T-03-03" severity="low">
JSON.stringify on the done event payload may throw if an offer object contains a non-serializable value. validateOffer() filters offers before they enter allOffers, so only schema-valid objects reach JSON.stringify. Mitigated by the existing validateOffer filter applied in each scraper's .then() callback.
</threat>
</threats>
<mitigations>All threats are mitigated in the implementation tasks below. No high-severity threats identified — this is a localhost tool with no authentication requirements and a single concurrent user.</mitigations>
</threat_model>

Insert a new `app.get('/api/scrape-stream', async (req, res) => { ... })` handler into server.js between the closing `})` of the POST /api/scrape handler (line 75) and the `app.get('/api/offers', ...)` line (line 77). Add a blank line before and after the new handler to maintain readability.

The handler body must do the following steps in this exact order:

1. Set four response headers using res.setHeader():
   - 'Content-Type' → 'text/event-stream'
   - 'Cache-Control' → 'no-cache'
   - 'Connection' → 'keep-alive'
   - 'X-Accel-Buffering' → 'no'

2. Call res.flushHeaders() with no arguments.

3. Call req.socket.setTimeout(0) with no arguments.

4. Parse duration from req.query: `const dur = parseInt(req.query.duration, 10)` and advancePayment: `const adv = parseInt(req.query.advancePayment, 10) || 0`.

5. Validate duration: if `!VALID_DURATIONS.includes(dur)`, write the error event string `event: error\ndata: {"error":"Invalid duration. Must be 12, 24, 36, or 48."}\n\n` using res.write(), then call res.end() and return.

6. Build the params object: `const params = { duration: dur, advancePayment: adv }`.

7. Declare `let aborted = false` and attach `req.on('close', () => { aborted = true })`.

8. Declare `const allOffers = []` and `const errors = []`.

9. Write initial "running" events synchronously (before building scraperPromises) by iterating over SCRAPERS with a for...of loop. For each `{ name }` entry, if `!res.writableEnded`, call res.write() with the string: `event: progress\ndata: ${JSON.stringify({ source: name, status: 'running', count: 0, error: null })}\n\n`

10. Build scraperPromises by mapping over SCRAPERS: for each `{ name, fn }`, call `fn(params).then(offers => { ... }).catch(err => { ... })`. In the .then() callback: (a) filter offers using `offers.filter(o => validateOffer(o).valid)` into a `valid` constant, (b) push all valid offers into allOffers with `allOffers.push(...valid)`, (c) if `!aborted && !res.writableEnded`, write a progress event with payload `{ source: name, status: 'done', count: valid.length, error: null }`. In the .catch() callback: (a) push to errors array: `errors.push(\`${name}: ${err.message || 'Unknown error'}\`)`, (b) if `!aborted && !res.writableEnded`, write a progress event with payload `{ source: name, status: 'error', count: 0, error: err.message || 'Failed' }`.

11. Call `await Promise.allSettled(scraperPromises)`.

12. Sort allOffers ascending: `allOffers.sort((a, b) => a.monthlyPrice - b.monthlyPrice)`.

13. Update store: `store = { offers: allOffers, scrapedAt: new Date().toISOString(), errors }`.

14. If `!aborted && !res.writableEnded`, write the done event using res.write() with the string: `event: done\ndata: ${JSON.stringify({ offers: store.offers, scrapedAt: store.scrapedAt, errors: store.errors, count: store.offers.length })}\n\n`

15. Call res.end() unconditionally (outside the aborted guard — it is safe to call end() on an already-ended or closed response; Node ignores it).

The event wire format for every res.write() call must use template literals with literal `\n` newline characters (not \\n escape sequences) to produce the SSE double-newline terminator. Example pattern: `res.write(\`event: progress\ndata: ${JSON.stringify(payload)}\n\n\`)`
